# Predictive Cyber Behavior Modeling Using Graph Neural Networks

A research pipeline that applies Graph Neural Networks to the CICIDS2017
intrusion detection dataset. Network traffic flows are converted into host-level
graphs and GNN models learn to classify nodes (IP hosts) as benign or malicious.

**Author:** Mohamed Salem Eddah
**Institution:** Shandong University of Technology
**Dataset:** CICIDS2017 — Canadian Institute for Cybersecurity Intrusion Detection System 2017

## Overview

Traditional intrusion detection systems treat network flows as independent records.
This project instead models an entire network capture session as a **directed graph**
where:

- **Nodes** represent IP addresses (hosts)
- **Edges** represent aggregated traffic between host pairs
- **Node features** encode traffic statistics, degree centrality, and attack involvement
- **Node labels** are binary: `0` (benign host) or `1` (malicious host)

Graph Neural Networks can propagate information across this topology — a host that
communicates with many known-malicious nodes should itself be flagged, even if its
individual flows look benign. This message-passing behaviour is the core advantage
over tabular machine learning.

### Models Implemented

| Name | Architecture | Key Property |
|------|-------------|--------------|
| GCN | Graph Convolutional Network (Kipf & Welling, 2017) | Spectral convolution |
| GAT | Graph Attention Network (Velickovic et al., 2018) | Learnable attention weights |
| GraphSAGE | Hamilton et al., 2017 | Inductive, neighbourhood sampling |
| HybridGNN | GCN + GAT + GraphSAGE ensemble | Multi-architecture fusion |
| TemporalGNN | GNN + LSTM | Captures time-evolving attack patterns |

### Graph Construction Methods

| Method | Description |
|--------|-------------|
| `host_based` | One node per IP address; edges = aggregated flows |
| `flow_based` | One node per flow record; edges = shared endpoints |
| `hierarchical` | Three-level: subnet → host → port |

## Architecture

```
Raw CICIDS2017 CSV files
        |
        v
[CICIDS2017Loader]
  - Multi-file loading with encoding fallback
  - Missing value imputation
  - Duplicate removal
  - Label encoding (15 attack types)
  - Feature engineering (ratios, flags, temporal)
  - Outlier capping (IQR / z-score)
  - Robust normalization
  - Rare class augmentation (optional)
        |
        v
[AdvancedGraphConstructor]
  - Host-based / flow-based / hierarchical graph
  - NetworkX -> PyTorch Geometric conversion
  - Node features (15 per node)
  - Edge features (5 per edge)
  - Temporal snapshot generation
  - Feature caching
        |
        v
[GNNTrainer + Model]
  - Stratified train/val/test split (60/20/20)
  - Weighted cross-entropy for class imbalance
  - Early stopping with patience
  - Gradient clipping (max norm 1.0)
  - LR scheduling (plateau or cosine)
  - AMP autocast (CUDA)
  - TensorBoard logging
  - SHAP feature importance
        |
        v
[Results]
  - Accuracy, Precision, Recall, F1, ROC-AUC
  - Confusion matrix
  - Training curves
  - Interactive graph HTML
  - Benchmark comparison table
```

## Dataset

The CICIDS2017 dataset is generated by the Canadian Institute for Cybersecurity.
It contains labelled network flows covering a full work week (Monday to Friday).

| Property | Value |
|----------|-------|
| Total records | ~2.83 million flows |
| Features | 78 original + engineered features |
| Classes | 15 attack types + BENIGN |
| Attack ratio | ~19.7 % malicious |
| Format | CSV (one file per day) |

|----|-------|----------|----------|
| 0 | BENIGN | Normal | 0 |
| 1 | DoS Hulk | DoS | 3 |
| 2 | PortScan | Reconnaissance | 2 |
| 3 | DDoS | DoS | 4 |
| 4 | DoS GoldenEye | DoS | 3 |
| 5 | FTP-Patator | Brute Force | 3 |
| 6 | SSH-Patator | Brute Force | 3 |
| 7 | DoS slowloris | DoS | 3 |
| 8 | DoS Slowhttptest | DoS | 3 |
| 9 | Bot | Botnet | 4 |
| 10 | Web Attack - Brute Force | Web Attack | 3 |
| 11 | Web Attack - XSS | Web Attack | 3 |
| 12 | Web Attack - SQL Injection | Web Attack | 4 |
| 13 | Infiltration | Infiltration | 4 |
| 14 | Heartbleed | Vulnerability Exploit | 5 |

## Installation

### Requirements

- Python 3.10 or later
- PyTorch 2.0 or later
- CUDA toolkit (optional, but recommended for large datasets)

### Step 1 — Clone the repository

```bash
git clone https://github.com/ze3tar/gnn-cyber-project.git
cd gnn-cyber-project
```

### Step 2 — Create a virtual environment

```bash
python -m venv venv
source venv/bin/activate        # Linux / macOS
# or
venv\Scripts\activate           # Windows
```

### Step 3 — Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

For PyTorch Geometric, match the versions to your CUDA installation.
See https://pytorch-geometric.readthedocs.io/en/latest/install/installation.html
for the correct install commands. A typical CPU-only install:

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
pip install torch-geometric
```

### Step 4 — Place the dataset

Copy or symlink the CICIDS2017 CSV files into `data/raw/CICIDS2017/` as shown
in the Dataset section above.

### Step 5 — Verify the installation

```bash
python -c "import torch; from torch_geometric.data import Data; print('Setup OK')"
```

## Configuration

All settings are controlled through `config.yaml`. The file is divided into sections:

### Data

```yaml
data:
  raw_dir: "data/raw/CICIDS2017"   # Path to CSV files
  processed_dir: "data/processed"  # Where to save preprocessed CSV
  graph_dir: "data/graphs"         # Where to save graph objects
  sample_size: null                # null = full dataset; integer for quick tests
```

Set `sample_size: 50000` for fast iteration during development.

### Preprocessing

```yaml
preprocessing:
  normalize: true              # Apply RobustScaler to numeric features
  handle_outliers: true        # Cap outliers using IQR method
  engineer_features: true      # Create ratio, flag, and temporal features
  deduplicate: true            # Remove ~11% duplicate records
  augment_rare: false          # Oversample classes with < 500 samples
  outlier_method: "iqr"        # "iqr" or "zscore"
  outlier_threshold: 3.0
  normalization_method: "robust"  # "robust", "standard", or "minmax"
```

### Graph Construction

```yaml
graph:
  construction_method: "host_based"  # "host_based", "flow_based", "hierarchical"
  time_window: 300                   # Seconds per temporal snapshot
  directed: true
  aggregate_edges: true              # Merge parallel flows into one edge
  min_flows: 1                       # Minimum flows required to create an edge
```

### Model

```yaml
model:
  type: "gcn"         # "gcn", "gat", "sage", "hybrid", "temporal"
  hidden_dim: 128
  num_layers: 3
  dropout: 0.5
  num_heads: 4        # GAT only
  aggregator: "mean"  # GraphSAGE only: "mean", "max", "lstm"
  lstm_layers: 2      # TemporalGNN only
  gnn_type: "gcn"     # TemporalGNN only: base GNN type
```

### Training

```yaml
training:
  num_epochs: 200
  learning_rate: 0.001
  weight_decay: 0.0005
  patience: 30          # Early stopping patience
  scheduler_type: "plateau"  # "plateau" or "cosine"
  use_class_weights: true    # Weight loss by inverse class frequency
  use_amp: false             # Mixed precision (requires CUDA)
```

### Evaluation

```yaml
evaluation:
  train_ratio: 0.6
  val_ratio: 0.2
  test_ratio: 0.2
  random_state: 42
```

## Running the Pipeline

The pipeline supports seven execution modes selected via `--mode`:

| Mode | Description |
|------|-------------|
| `full` | Run everything end-to-end (default) |
| `preprocess` | Data loading and feature engineering only |
| `graph` | Graph construction from preprocessed data |
| `train` | Train and evaluate a single model |
| `benchmark` | Train and compare all architectures |
| `temporal` | Train the TemporalGNN on snapshot sequences |
| `evaluate` | Re-evaluate a saved checkpoint |

### Full pipeline (recommended first run)

```bash
python main_pipeline.py --config config.yaml --mode full
```

This runs all three phases: preprocessing, graph construction, and training.

### With a config override

```bash
python main_pipeline.py --config config.yaml --mode full --model gat
```

## Temporal GNN Training

The TemporalGNN combines a spatial GNN with a two-layer LSTM to model how
attack patterns evolve over time. It requires the dataset to contain a
`timestamp` column (present in CICIDS2017).

```bash
# Step 1: Preprocess
python main_pipeline.py --mode preprocess

# Step 2: Train temporal model
python main_pipeline.py --mode temporal
```

The temporal mode:

1. Divides the dataset into 5-minute time windows
2. Builds one graph snapshot per window
3. Trains the TemporalGNN on sliding sequences of 5 consecutive snapshots
4. Predicts whether the next time window contains an attack

Training history is saved to `results/temporal_evaluation/training_history.json`.

python main_pipeline.py --mode evaluate \
    --checkpoint models/checkpoints/best_model.pt

This loads the saved weights, rebuilds the model from the current config,

## Advanced Options

### Enable Automatic Mixed Precision (AMP)

Requires a CUDA GPU. Provides roughly 2x training speed and halves memory use.

```yaml
# config.yaml
training:
  use_amp: true
```

### Enable rare class augmentation

Heartbleed (11 samples) and SQL Injection (21 samples) are extremely rare.
Enabling augmentation duplicates these classes with small Gaussian noise
until they reach 500 samples, preventing the model from ignoring them.

```yaml
# config.yaml
preprocessing:
  augment_rare: true
```

### Use flow-based graph construction

```yaml
graph:
  construction_method: "flow_based"
```

Each flow becomes a node; edges connect flows that share a source or
destination IP. This captures more fine-grained attack signatures than
host-level aggregation.

### Use hierarchical graph construction

```yaml
graph:
  construction_method: "hierarchical"
```

Three-level graph: subnet (e.g., 192.168.1.0/24) -> host -> port. Useful
for studying lateral movement patterns within subnets.

### Change the LR scheduler

```yaml
training:
  scheduler_type: "cosine"   # or "plateau"
```

Cosine annealing decays the learning rate smoothly to a minimum of 1e-6
over `T_max = 100` epochs. Plateau reduces by factor 0.5 whenever
validation loss stops improving for 10 epochs.

### Run with a custom config file

```bash
python main_pipeline.py --config experiments/my_experiment.yaml --mode full
```

This lets you maintain separate config files for different experiments without
modifying the default `config.yaml`.

### Clear cached node features

Delete the cache directory to force recomputation:

```bash
rm -rf data/cache/
```

## Troubleshooting

### "No CSV files found in data/raw/CICIDS2017"

The raw dataset directory is empty or the path in `config.yaml` is incorrect.
Check that the CSV files exist:

```bash
ls data/raw/CICIDS2017/*.csv
```

### "Processed data not found"

The preprocessing step has not been run yet. Run it first:

```bash
python main_pipeline.py --mode preprocess
```

### "Graph file not found"

Graph construction has not been run. Run:

```bash
python main_pipeline.py --mode graph
```

### Out of memory during preprocessing

Set a sample size in `config.yaml`:

```yaml
data:
  sample_size: 100000
```

Or enable chunked loading by modifying the loader call in the pipeline
to pass `chunksize=100000`.

### Training is very slow (CPU only)

Install PyTorch with CUDA support for your GPU and set in `config.yaml`:

```yaml
resources:
  device: "cuda"

training:
  use_amp: true
```

### "Config missing required key" at startup

The config file is missing a required field. Compare your config against
`config.yaml` in the repository and add any missing keys.

### TensorBoard shows no data

Ensure at least one training epoch has completed, then refresh the browser.
Verify the log directory:

```bash
ls logs/tensorboard/
tensorboard --logdir logs/tensorboard
```

### SHAP analysis is skipped

Install the optional dependency:

```bash
pip install shap>=0.44.0
```

NumPy, PyTorch, and CUDA. Set via `config.yaml`:

```yaml
seed: 42
deterministic: true
```

Or call from code:

```python
from src.utils import set_seed
set_seed(42)
```
